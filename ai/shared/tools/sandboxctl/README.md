# sandboxctl

`sandboxctl` is the command-line orchestrator for sandbox lifecycle operations (init, list, destroy, prune) within the workspace. It enforces the backup-before-destructive-command policy by requiring signed backup approval tokens generated by `backupctl`.

## Key Concepts
- **Sandbox registry**: Derived from `workspace.yaml`; determines sandbox metadata, location, and ownership.
- **Backup enforcement**: Destructive commands (e.g., `destroy`, `prune`) fail unless a valid backup token (`--backup-token`) referencing a fresh, hash-verified backup exists.
- **Dry runs**: Use `--dry-run` to preview operations without mutating state.
